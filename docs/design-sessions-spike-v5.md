## §1 Goals

Two operator-confirmed features for the dashboard, both extending the v4
sessions surface:

- **F1 — rating-survey context.** When the operator rates a session, the
  survey must remind them *what the session was* — the Claude-generated
  title, the prompts asked, and a compact summary of what was done. Today
  `RatingSurvey.vue` shows only the nine bare KPI questions, which directly
  undermines v4's UC-1 ("capture judgment while memory is fresh").
- **F2 — AI cost per vendor, in every view.** Every Sessions view and every
  repo/project view must surface AI spend, broken down by vendor
  (Anthropic / OpenAI / Google). Cost is *derived* from telemetry the
  vendors' own tools already leave on disk — the dashboard becomes a reader
  of that telemetry, never an instrumenter of it.

## §2 Scope

**In scope**

- Parsing per-message **token usage + model** from Claude Code transcripts.
- A new read-only reader for **Codex** run telemetry under
  `~/.codex/sessions/` (live tree only — see §4.2).
- A new read-only reader for the **metaswarm external-tools ledger**
  (`~/.claude/sessions/external-tools.jsonl`) — the only Gemini cost source.
- A pinned, in-repo **model→price table** and a tokens→USD cost calculator.
- A **cwd→project attribution** resolver shared by the Codex + ledger readers.
- Per-session Claude cost; per-repo per-vendor cost aggregation.
- Cost widgets in the Sessions list, the session detail, and the repo views.
- The F1 survey-context panel (title + prompts + action summary).

**Out of scope**

- Any new **write** endpoint or write surface. v5 is read-only; the v4 write
  API (PUT rating) and its `method-guard` allow-list are untouched.
- **Instrumenting or wrapping** Codex/Gemini invocations. We read only what
  already lands on disk.
- **`~/.codex/archived_sessions/`** — the rotated Codex tree. v5 reads only
  the live `~/.codex/sessions/` tree; archived runs are a follow-up bead
  (§13). This bounds the directory walk.
- **Fixing metaswarm's** broken external-tools adapter (tracked: bead
  `metaswarm-dashboard-d2u`, to be reported upstream).
- **Live price fetching** / any network call. Prices are pinned in-repo.
- **Heuristic per-session delegation attribution** (§4.4 — operator
  decision: repo-level attribution only).
- Recovering **historical Gemini cost** — none exists on disk (§4.3).

## §3 Background

v4 made the dashboard read Claude Code transcripts under `~/.claude/projects/`
and rate sessions. v5 builds on that:

- The transcript parser (`packages/sessions/src/jsonl-reader.ts`) already
  walks every transcript but **drops** `message.usage` / `message.model`,
  and its `mapEntry` early-returns `[]` for any record `type` other than
  `user` / `assistant` — so the `ai-title` record is discarded before it
  reaches the timeline. v5 stops dropping both.
- Two other AI vendors are reachable on this machine — Codex CLI and Gemini
  CLI, both delegated to by metaswarm's external-tools workflow. Their cost
  telemetry lives in different places with different recoverability
  (§4.2, §4.3).

## §4 Data sources & shapes

> All record shapes below were verified against real files on this machine
> during the design-review gate. Implementation fixtures MUST be **redacted
> copies of real files** (a real transcript, a real Codex rollout) — and,
> since no real ledger exists, a ledger fixture generated by running
> `emit_json` from metaswarm's `_common.sh`. Hand-authored JSON fixtures are
> forbidden (they caused the v4 "dead KPI" failure).

### §4.1 Anthropic / Claude — `~/.claude/projects/**/*.jsonl`

Each `assistant` record carries:

```
message.model  → e.g. "claude-opus-4-7"
message.usage  → {
  input_tokens, output_tokens,
  cache_read_input_tokens,
  cache_creation_input_tokens,          // top-level: the 1h+5m sum
  cache_creation: { ephemeral_1h_input_tokens, ephemeral_5m_input_tokens }
}
```

- `costUSD` exists on the record but is `null` — cost is **computed** by v5.
- v5 uses the **top-level** `usage.input_tokens` / `output_tokens` /
  `cache_read_input_tokens`, and the **`cache_creation.ephemeral_1h/5m`
  split** for cache-write pricing. The `usage.iterations[]` array is **not**
  summed — the top-level figures are already cumulative for the record.
- Per-session cost = the sum over the session's `assistant` records, **main
  thread and `isSidechain` subagent records** (all share one `sessionId` /
  file). Recoverable **retroactively** for every transcript on disk. Vendor
  is always `anthropic` for a Claude Code session.

### §4.2 OpenAI / Codex — `~/.codex/sessions/<YYYY>/<MM>/<DD>/rollout-*.jsonl`

Codex CLI writes one `rollout-<ts>-<uuid>.jsonl` per run (interactive *and*
`codex exec`, which metaswarm uses). Relevant records:

```
session_meta.payload  → { cwd, originator, source, ... }   (run identity + repo)
turn_context.payload.model                                 (e.g. "gpt-5.5")
event_msg, payload.type == "token_count":
  payload.info  → null   (emitted at least once, early in the run)
  payload.info  → { total_token_usage: { input_tokens, cached_input_tokens,
                      output_tokens, reasoning_output_tokens, total_tokens },
                    last_token_usage: {...}, model_context_window }
```

- **Token usage = the last `token_count` record whose `payload.info` is
  non-null**, then `info.total_token_usage`. A `token_count` record with
  `info: null` is skipped. **A rollout with *zero* non-null-`info`
  `token_count` records** (an interrupted run — verified to occur) yields
  `costUsd: null` / `priced: false` — explicitly **not `0`**. The fixture
  set MUST include one such `info`-null-only rollout.
- **Model** = the **last** `turn_context` record's `payload.model` (a run may
  span multiple turns; the final model is representative).
  `session_meta.payload.model` is unreliable (`null` in samples) — do not use.
- **cwd** = `session_meta.payload.cwd`.
- v5 reads `~/.codex/sessions/` **directly** — it does *not* trust
  metaswarm's ledger for Codex, because metaswarm's `extract_cost_codex()`
  reads a `.usage` key Codex 0.130 no longer emits (bead `d2u`).
  `~/.codex/archived_sessions/` is out of scope (§2).

### §4.3 Google / Gemini — `~/.claude/sessions/external-tools.jsonl`

Gemini CLI persists **nothing** to disk — token usage exists only on
`--output-format json` stdout at invocation time. The single capture point
is metaswarm's external-tools adapter, which appends one envelope per run.
The **real** record shape (from `emit_json` / `log_session` in metaswarm's
`skills/external-tools/adapters/_common.sh`) is:

```
{ schema_version, tool, command, model, attempt, exit_code, branch,
  git_sha, files_changed, diff_stats, duration_seconds,
  cost: { input_tokens, output_tokens }, raw_log, error_type, timestamp }
```

v5's reader:

- Parses each line with a **Zod schema that `.pick()`s only**
  `schema_version`, `tool`, `model`, `cost`, `timestamp`, `git_sha` — so
  `command` and `raw_log` (both secret-bearing) are **structurally dropped
  at parse time** and cannot leak via a future code change (§9).
- Targets a known `schema_version`; an entry with an unrecognized version is
  **skipped and counted** (mirrors v4's `skippedLineCount`).
- Feeds Google cost only from entries where `tool == "gemini"`. `tool ==
  "codex"` entries are ignored (Codex is read directly, §4.2).
- **Costs failed runs too**: `exit_code != 0` / `error_type` set still
  consumed billed tokens, so the run is still costed; the design does not
  filter on exit status.

Consequences, accepted:

- **No historical Gemini cost is recoverable** — the ledger has never been
  written in this environment.
- v5 ships the reader with a graceful **empty state** ("no Gemini
  delegations recorded yet") when `external-tools.jsonl` is absent.

### §4.4 Attribution (cwd → project)

Operator decision — **repo-level, no heuristics**:

- Cost is keyed on the **config.yaml project namespace** — the same
  `Config.projects` set that `discoverSessions` already uses. This is
  distinct from the *snapshot* project namespace that `SnapshotReader`
  (and `/api/projects`) reads from the datalake; §7 specifies the join.
- A shared **`resolveProjectForCwd`** resolver (a new module — §10 `v5-1`,
  reused by the Codex and ledger readers) maps a run's `cwd` /
  `git_sha`-derived path to a configured project. Matching is an
  **exact-or-prefix comparison on `realpath`-resolved absolute paths** —
  never a substring match (so project `repo` cannot capture `repo-secret`).
- A run whose path matches no configured project is bucketed as
  **`unattributed`** and shown only in a global total — never silently
  dropped.
- A **Claude Code session** maps to one project (v4 already does this); its
  cost is attributed there and shown in the Sessions views.
- Codex/Gemini runs are **delegations, not rateable sessions** — they never
  appear as rows in the Sessions list. Their cost surfaces only in
  repo-level aggregates. No attempt is made to bind a delegation to the
  Claude session that spawned it.

## §5 Cost model

### §5.1 Pricing table

A pinned, version-controlled JSON resource:
`packages/sessions/src/cost/model-prices.json`, validated by a Zod schema.
The `packages/sessions` build copies `src/cost/*.json` into `dist/` so the
table is reachable at runtime.

```
{
  "pricingAsOf": "YYYY-MM-DD",
  "source": "<vendor public pricing-page URLs, in a sibling .md or comment>",
  "models": {
    "claude-opus-4-7": { "input":…, "output":…, "cacheRead":…,
                         "cacheWrite5m":…, "cacheWrite1h":… },
    "gpt-5.5":         { "input":…, "output":…, "cacheRead":… },
    "gemini-…-pro":    { "input":…, "output":… },
    …
  }
}
```

- Prices are **per 1M tokens, USD**. `pricingAsOf` is surfaced in the UI
  (§8.2) so stale prices are visible.
- **v5 ships prices for the models observed on this machine**: the Claude
  4.x family in use (`claude-opus-4-7`, the Sonnet 4.x and Haiku 4.5 ids),
  the Codex model(s) (`gpt-5.5` / `gpt-5.3-codex`), and the Gemini model.
  Exact ids and numeric rates are populated **at implementation time from
  the vendors' public pricing pages**, with `pricingAsOf` and a cited
  `source`. **Every other model id deliberately renders unpriced on day
  one** (§5.3).
- Model-id matching is **exact**, after a documented normalization of known
  dated-suffix aliases. No fuzzy matching.
- **The cost-calculator unit tests use a FIXED in-test pricing table**, not
  the shipped JSON — so editing real prices never breaks calculator tests.
  The shipped JSON gets its own separate schema-validation test.

### §5.2 Computation

For one priced model's usage, USD:

```
cost = ( input_tokens                  × input
       + output_tokens                 × output
       + reasoning_tokens              × output                       // Codex
       + cache_read_tokens             × (cacheRead    ?? input)
       + ephemeral_5m_cache_creation   × (cacheWrite5m ?? cacheWrite ?? input)
       + ephemeral_1h_cache_creation   × (cacheWrite1h ?? cacheWrite ?? input)
       ) / 1_000_000
```

- **Anthropic**: `cache_creation` is split — 5m and 1h writes are priced
  with their own table keys. A model entry omitting a split key falls back
  to a blended `cacheWrite`, then to base `input` (documented, conservative).
- **Codex**: `cached_input_tokens` is billed at `cacheRead ?? input`;
  `reasoning_output_tokens` at `output`. Codex has no cache-write split.
- Each `§5.2` term names exactly which source field it reads (above).

### §5.3 Unknown models

An id absent from the table yields `costUsd: null`, `priced: false`. The UI
shows **"n/a"** with an explaining tooltip — **never a fabricated `0`**
(§8.2). A `0` would be indistinguishable from a genuinely free/zero run.

### §5.4 Caching (compute-on-read, two levels)

Cost is **computed on read, never persisted** (persisting would freeze a
stale price). Two cache levels, both in-memory, LRU-bounded (256 entries,
mirroring v4 `transcript-cache.ts`):

1. **Per-file leaf cache** — the parsed + costed result of one transcript or
   one Codex rollout, keyed by `(path, mtime, size)`.
2. **Per-project aggregate cache** — a `ProjectCostSummary`, keyed by
   `(sorted source-path set, max mtime over the set, pricing-table content
   hash)`. Recomputed only when a source file is added/changed or the price
   table changes.

The pricing table's cache key is a **content hash**, not mtime — a `git
checkout` rewrites mtime without changing content, and vice versa. The
per-file source cache keeps v4's `(mtime, size)` key, which is correct there.

This bounds a `GET /api/projects` request: the index scans the source set
once, then serves the aggregate cache on subsequent loads.

## §6 Schemas (new — `packages/types`)

Additive; no v4 schema is broken.

- `TokenUsage` — `{ inputTokens, outputTokens, cacheCreationTokens,
  cacheReadTokens, reasoningTokens }` (all int ≥ 0).
- `ModelPricing` / `PricingTable` — the §5.1 file schema.
- `VendorId` — `z.enum(['anthropic','openai','google'])`.
- `VendorCost` — `{ vendor: VendorId, model: string, usage: TokenUsage,
  costUsd: number | null, priced: boolean }`.
- `SessionCost` — a Claude session's own cost: `{ sessionId,
  vendor: 'anthropic', byModel: VendorCost[], totalCostUsd: number,
  hasUnpriced: boolean }`.
- `DelegationRun` — one Codex/Gemini run: `{ vendor, model,
  projectName: string | null, at, usage, costUsd: number | null }`.
- `ProjectCostSummary` — per repo: `{ projectName,
  byVendor: Record<VendorId, { costUsd: number; runCount: number;
  hasUnpriced: boolean }>, totalCostUsd: number, hasUnpriced: boolean,
  pricingAsOf: string }`.

**`totalCostUsd` / `hasUnpriced` semantics (explicit):** `totalCostUsd` is
always the **sum of the priced contributions** (a number, possibly `0`).
`hasUnpriced` is `true` when at least one contributing model was unpriced —
meaning `totalCostUsd` is a **lower bound**. The UI renders a lower-bound
total distinctly (e.g. `"$4.20 + unpriced"`), never a bare number and never
"n/a" (§8.2). A truly empty project: `totalCostUsd: 0, hasUnpriced: false`.

Extended v4 schemas (additive fields only):

- `SessionTimeline` → `aiTitle: string | null` (the last `ai-title` record's
  value; `null` when absent — the common case, ~85% of transcripts).
- `SessionSummary` → `aiTitle: string | null`, `costUsd: number | null`
  (equals the session's `SessionCost.totalCostUsd`; `null` only when the
  session has no costable records).

## §7 Server API

All additions are **read-only GETs**. No write surface is added; the v4
`method-guard` allow-list is unchanged.

- `GET /api/sessions` — `SessionSummary[]` now carries `aiTitle` + `costUsd`.
- `GET /api/sessions/:project/:sessionId` — detail gains `cost: SessionCost`;
  `timeline.aiTitle` is populated.
- `GET /api/projects` (index) — each project row gains `totalCostUsd` +
  `hasUnpriced`.
- `GET /api/projects/:name` (detail) — gains `cost: ProjectCostSummary`.
- `pricingAsOf` rides along on every cost-bearing response.

**Project-namespace join (Architect blocker A1).** Cost aggregation keys on
the **config.yaml project name**. `/api/projects` and `/api/projects/:name`
are served from the **snapshot** namespace (`SnapshotReader`). The two are
joined **by project name**:

- A project in both namespaces → snapshot row + its cost.
- A project in config.yaml only (cost data, no snapshot) → still rendered,
  as a cost-only row.
- A project in the snapshot only (no config entry, no cost) → still
  rendered, with `totalCostUsd: 0, hasUnpriced: false`.
- Cost that resolves to no configured project → the `unattributed` bucket,
  surfaced in a global total on the projects index.

Each new read path reuses the v4 mtime-cache pattern (§5.4).

## §8 UI

All survey/cost content is rendered as **text, never HTML** (`v-html` is
never used) — consistent with v4's `SessionEventTimeline` / `RatingSurvey`.
Long strings reuse the existing `truncateSummary` helper.

### §8.1 F1 — survey context

`SessionDetailView.vue` passes the already-fetched `timeline` to
`RatingSurvey.vue`, which renders a **bordered context panel above the KPI
rows** (the panel's own internal expanders never push the 9 KPI rows down):

- **Heading** — the `aiTitle`; when `null`, `"Untitled session"`.
- **Prompts** — the first user prompt, taken from
  `timeline.events.filter(e => e.kind === 'user-prompt')` (`user-command`
  events — slash-commands — are **excluded**). A "show all N prompts"
  control expands the remaining prompts **inline within the panel**. When
  the session has zero user prompts, the prompts block is **omitted
  entirely** (no blank heading).
- **Action summary** — tool-use counts grouped by `toolName` over
  `events.filter(e => e.kind === 'tool-use')`, descending by count, rendered
  e.g. `"Read ×12 · Edit ×8 · Bash ×5 · Agent ×2"`. Zero tool-uses →
  `"no tool calls recorded"`. (The "first ~8 events" alternative is dropped
  — it would duplicate the `SessionEventTimeline` already on the page.)

### §8.2 F2 — cost widgets

- **Sessions list** (`SessionsView.vue`) — a **"Cost"** column added after
  "Events". Rendering: `null` → `"n/a"`; `0` → `"$0.00"`; an in-progress
  session → its partial cost (consistent with v4's in-progress event count).
  USD is formatted with enough precision to distinguish sub-cent sessions
  (4 decimals, e.g. `"$0.0123"`). The Session cell additionally shows
  `aiTitle` as a title line **above** the existing `<sid[:8]>` suffix — the
  suffix is **kept** (it is the only same-minute disambiguator; v4 §6.2).
- **Session detail** (`SessionDetailView.vue`) — a cost panel: the
  `SessionCost.byModel` breakdown (per model: input / output / cache tokens
  and USD) and the session total.
- **Projects index** (`ProjectsIndex.vue`) — each project card shows its
  total AI cost; when `hasUnpriced`, `"$X + unpriced"`.
- **Project detail** (`ProjectDetail.vue`) — a **fifth `<section>`** ("AI
  cost"), following the existing `<section><h2>` small-caps pattern. Rows
  for **all three vendors** Anthropic / OpenAI / Google — a vendor with no
  runs shows `"$0.00 (0 runs)"` (never omitted, so the operator sees it was
  considered). Each row: run/session count, tokens, USD.
- **Unpriced** model cost renders `"n/a"` with the tooltip *"Model `<id>` is
  not in the pricing table — cost cannot be computed."*
- The **`pricingAsOf` caveat** is rendered **once per view** (a small
  footnote under the table / card grid), e.g. *"AI prices as of
  YYYY-MM-DD"* — not repeated on every figure.

## §9 Security & privacy

- **Recursive-walk hardening (Security blocker S1).** The Codex reader does
  a recursive descent of `~/.codex/sessions/<YYYY>/<MM>/<DD>/`. v4's
  flat-layout hardening is insufficient for a tree, so the Codex walk MUST:
  - `lstat` **every directory level** and **refuse (not follow)** a
    symlinked directory;
  - re-assert `realpath` containment under the resolved
    `CODEX_SESSIONS_DIR` **at each level**;
  - apply the `^[A-Za-z0-9._-]+$` + `..`-reject sanitizer to **every path
    segment**, not just a leaf basename;
  - bound the walk: **max depth 4** (the fixed `YYYY/MM/DD/file` shape) and a
    **max-files-visited cap**;
  - exclude `~/.codex/archived_sessions/` (§2).
- **Per-file / per-line caps.** Both new readers reuse v4's per-line
  `MAX_LINE_BYTES` cap and malformed-line skipping. The ledger reader adds a
  **total-file-size cap** (a single append-only file could grow unbounded).
- **Allow-list parsing (Security blocker S2).** The Codex and ledger readers
  parse via Zod schemas that **pick only the allow-listed fields** (§4.2,
  §4.3). The ledger `command` and `raw_log`, and any Codex prompt/response
  text, are **structurally dropped at parse time** — never read into memory,
  never reachable by a later code change.
- **F1 widens secret exposure — acknowledged (extends v4 §8.3).** F1
  surfaces full user-prompt text and `aiTitle` in the survey UI. Like v4's
  200-char tool-use `summary`, this **may contain operator secrets**, and
  more so (full prompt bodies). Accepted: the dashboard is localhost-only —
  no CORS, no telemetry, no outbound fetch — so secrets never leave the
  machine. The v4 WU-1 in-repo secret-scan does **not** cover this (prompts
  are not in-repo); this is a deliberate, documented acceptance, not an
  oversight.
- **Env-var paths.** `METASWARM_DASHBOARD_CODEX_SESSIONS_DIR` and
  `METASWARM_DASHBOARD_EXTERNAL_TOOLS_LEDGER` mirror v4's
  `METASWARM_DASHBOARD_TRANSCRIPTS_DIR` — server-process env, operator-set,
  used only as a `realpath` root. No request-controlled path concatenation.
- **Zero-footprint invariant unchanged** — all three sources are read-only;
  nothing is written to host repos; cost is computed in memory; **no new
  datalake file** is created (v4 ratings storage untouched).
- **No write surface** — §7 adds only GETs; the v4 write API + `method-guard`
  + §8.1 CSRF contract are not modified.
- **No network / supply-chain surface** — the pricing table is in-repo,
  version-controlled, Zod-validated; no fetch.

## §10 Work units (high level — refined in the plan)

1. `v5-1` — pricing table + Zod schemas (`§6`) + tokens→USD calculator
   (`§5.2`/`§5.3`) + the shared `resolveProjectForCwd` resolver (`§4.4`).
2. `v5-2` — Claude `usage`/`model` extraction in the transcript parser;
   per-session `SessionCost`.
3. `v5-3` — Codex rollout reader (`§4.2` shape, incl. the `info`-null edge
   case) + per-run `DelegationRun` + cwd attribution + the `§9` recursive
   hardening.
4. `v5-4` — Gemini ledger reader (`§4.3` real shape, allow-list parse) +
   empty-state.
5. `v5-5` — per-project per-vendor cost aggregation (`ProjectCostSummary`) +
   the §5.4 aggregate cache.
6. `v5-6` — `ai-title` capture in the parser (`mapEntry` gains an `ai-title`
   branch) → `SessionTimeline.aiTitle`.
7. `v5-7` — server API: extend the GETs, the §7 namespace join, the caches.
8. `v5-8` — F1 survey-context panel.
9. `v5-9` — F2 cost widgets: Sessions list + session detail.
10. `v5-10` — F2 cost widgets: repo views; integration test; docs; follow-up
    beads.

Each reader/parser WU's DoD must include a test against a **real-file
fixture** including the named edge cases (a `info`-null-only Codex rollout;
a transcript with **no** `ai-title`, the ~85% common case; an absent
ledger). Final decomposition, DoD, file scope, and the dependency DAG are
produced by the planning phase and pass the plan-review gate before
execution.

## §11 Anti-goals

- §11.1 No write surface, no new datalake file. v5 is read + compute only.
- §11.2 No instrumentation/wrapping of Codex/Gemini; no upstream metaswarm
  changes (bead `d2u` reports the adapter bug instead).
- §11.3 No network calls; no live/auto-updating prices.
- §11.4 No fuzzy model-id matching; no fabricated `0` for unpriced models.
- §11.5 No heuristic delegation→session binding (repo-level attribution).
- §11.6 Codex/Gemini runs are not rateable and never enter the Sessions list.
- §11.7 No `git push` (operator pushes); no `--no-verify`; coverage gate
  enforced per `.coverage-thresholds.json`.

## §12 Definition of Done

- All work units complete; build / typecheck / test / lint green; coverage
  meets `.coverage-thresholds.json`.
- Claude per-session cost is computed from `message.usage` (incl. the
  1h/5m cache split) and shown in the Sessions list column and the
  session-detail per-model panel.
- Codex runs are read from `~/.codex/sessions/`, costed (incl. the
  `info`-null edge → `null`, not `0`), and attributed to a project by cwd;
  the project per-vendor panel shows OpenAI cost.
- The Gemini ledger reader parses the real record shape via the allow-list
  schema and degrades to a clear empty state when the ledger is absent.
- Repo views show per-vendor cost; an unpriced model shows "n/a" (never
  `0`); a lower-bound total shows "$X + unpriced"; the "prices as of" caveat
  is visible once per view.
- The rating survey shows the session's `aiTitle` (or "Untitled session"),
  the prompts with an inline "show all" expander, and the tool-use action
  summary.
- New read sources carry the §9 recursive-walk hardening and allow-list
  parsing; no write surface added; host repos provably untouched.
- README + `docs/follow-ups/sessions.md` updated; STACK.md /
  decisions.jsonl reflect v5 decisions; ≥3 follow-up beads filed (incl. the
  `archived_sessions` reader and a lightweight F2 post-merge usage check
  mirroring v4 §10).

## §13 Follow-ups & open risks

- **`~/.codex/archived_sessions/`** — rotated Codex runs are unread in v5;
  a follow-up bead adds the archived-tree reader (with the same §9
  hardening) if historical OpenAI cost proves wanted.
- **Gemini history is unrecoverable** — accepted; cost accrues only from the
  first ledger write forward.
- **metaswarm adapter bug** (`d2u`) — reported upstream; until fixed, the
